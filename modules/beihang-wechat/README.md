# 公众号的后台网页整理

本模块只处理 `industry/wechat-accounts.json` 中已核对的公众号。公开搜索用于发现多篇文章，微信读书最新文章用于补查；这是网页检索渠道，不是公众号完整历史列表，不保证全部推送都被搜索引擎收录。

`collector/` 挂入本机 WeRSS 的独立容器，以普通无头 WebKit 浏览器点击公开搜索结果并读取微信文章。公开搜索使用独立浏览器资料，不导入公众号后台的登录凭据。没有桌面窗口、鼠标键盘模拟、反检测注入或第三方付费采集。公众号后台中属于用户自己的发表记录不作为目标账号的数据。无法读取或要求验证的网页会留下问题记录，不当作“没有新增”。

文章按原文 `biz` 核对账号，按原文 `ct` 读取发布日期；没有核验时间和足够正文的文章不进入摘要队列。公开文章编号 `biz / mid / idx` 用于去重；保留可用的微信原文链接，能取得短链接时优先使用短链接。公开搜索给出的签名链接可能过期，重新发现文章时刷新此类链接。不会把采集时间补成发表时间。

已核实改名的账号可在配置中填写 `previousNames` 与 `searchTerm`，用于匹配仍按旧名收录的搜索结果；新旧名称都必须通过同一个固定发布者 ID 核验。2026-11-11 已核实机械学院和人工智能学院的旧名索引，身份样本见 `docs/college-wechat-validation.json`，其中超过一年范围的文章仅用于核验身份，不导入站点。

2026-11-05 验证“智慧北航”时发现微信读书正文返回登录过期错误 `-2012`。此时用已取得的公开文章链接启动无头浏览器读取微信原文，仍验证响应、微信域名、发布者、原文日期与正文；要求验证或读取失败时按原规则记录问题。

`server.ts` 在已有 worker 中登记每分钟运行的到期检查器，只有启用且到期的目标账号才采集。它在数据库中原子预约下次检查时间，间隔固定 2880 分钟；失败、重启不会变成每分钟抓取。采集和整理分开：模型仍走原来的内容队列、回执和共享额度。后台信源页的手动检查会将该账号设为到期，不和正在进行的检查重叠。

## 本机配置

1. 采集容器使用 `deploy/wechat/compose.yaml`，端口只绑定 `127.0.0.1:3002`。运行凭据位于忽略提交的 `.data/wechat-collector/.env`；账号登录状态及浏览器资料保存在其 `data/` 下。
2. 主站数据卷中的 `/data/beihang-wechat.json` 只包含本机采集器的 `username` 与 `password`，权限应为 `0600`，由 Node 容器用户持有；不要放入站点配置、浏览器或对话。
3. 启动采集容器和更新后的主站，再在 API 容器运行 `node scripts/setup-wechat.ts` 登记账号。它保留后台已经暂停的账号。
4. 之后统一运行 `bash scripts/local-up.sh`；已有容器也会随 Docker 恢复运行。关闭浏览器不影响整理，电脑关机期间暂停，到期信息保留在数据库。

源检查结果会区分成功无新增、发现新资料、部分取得但未完成、失败。登录失效或网站要求人工验证时，公开检索仍会尽量继续；不能保证永不需要重新扫码。实际需要时只进行登录或验证，不要求用户搬运每篇文章。

## 验证

Python 解析测试可在采集容器运行：

```bash
docker compose -f deploy/wechat/compose.yaml exec -T wechat /app/env_x86_64/bin/python3 -m unittest discover -s /app/paian_collector/tests -v
```

数据库测试位于 `tests/collector.test.ts`，随主站 `npm test` 在独立测试数据库运行。涵盖并发预约、48 小时持久化、失败水位、被中断检查、手动重试、原始时间、发布者核验、签名轮换去重、模型零调用及暂停保留。
